# Settings window

Chrome and why it is AppKit-owned: [../architecture.md](../architecture.md). Localization rules: [../development.md](../development.md).

`SettingsView` / `SettingsRow`: a `NavigationSplitView` source list, panes built from `SettingsGroup` + `SettingsRow` (title and optional subtitle on the left, control on the right; `controlBelow: true` puts the control under the label). **A choice in a settings row is a pop-up menu** (`.pickerStyle(.menu)`), as in System Settings, never a segmented control: one control everywhere, and a menu fits beside its label however many options it has (Position's six segments had to move under the label to fit). Segmented controls are kept for switching what a view shows — Token activity's view, the recap's day / week / month / year. `SettingsPane` includes `.account(AccountKey)`, so every account — each provider's first, plus any added login — still has a pane. Built-in accounts are reached from the Providers page (and from a sidebar search); an extension keeps a row under Other.

## Where the code lives

All of it is in `Sources/Pulse/Settings`. `SettingsView.swift` is the shell only: the split view, the window's title and back/forward toolbar (the pane's name stays in the sidebar; a built-in account draws its own title and Back inside the pane), the switch that picks a pane, the search text, and the three models below. A pane is a view that draws rows; what a pane edits through a button is in a model.

**A model is the shell's when its state must outlive the pane** — a device-code sign-in polls for fifteen minutes, a browser read may wait on a keychain dialog, the ledgers are kept while the window is open — so switching panes neither discards it nor orphans the task writing to it. A pane's own state stays in the pane and resets with it.

**Three tasks stay on the shell's scroll view** — history (`AccountHistoryModel.key`), Token spend reading (`SpendPaneModel.loadKey`) and its summary (`summaryRequest`). Their keys include the selected pane and the window's visibility, and the release path (leave the pane, switch reading off, close the window) runs only if a task is still alive to see the key change. Moving one into a pane view would silently drop that path.

**A new pane** is a view in its own file, a `SettingsPane` case (`title`, `symbol`, `searchTerms`), and one line in the shell's `switch`.

**Search.** The sidebar is `.searchable(placement: .sidebar)`, **not** `.automatic`: the field belongs at the top of the list, under the traffic lights, as in System Settings; automatic would put it in the window's toolbar, which carries only the title. With the field empty, built-in accounts are not sidebar rows; they are on the Providers page. A search lists the matches in the sidebar again, in the same groups as that page, matched on the provider's name *as well as* the user's label (a second Claude subscription called "工作" is found by typing "claude"). A pane matches by its title **or** any of its rows' titles (`SettingsPane.searchTerms` — keep it in step when a row moves or is added). Matching is `localizedStandardContains` (case- and accent-insensitive, as Finder searches). A section with no matches is omitted; nothing matching leaves a "No matches" line. A search that hides the current selection does not clear it. The account whose pane is open stays as a sidebar row when the field is empty, so its selection tag is still in the list.

**The Providers page has its own field**, above the groups, with the same placeholder as the sidebar (**Search**, zh-Hans 搜索). It filters that page only. An empty field, including one that is only spaces, shows every built-in account. A query keeps a row whose label or product name contains it, with the same `localizedStandardContains` match, so the second Claude account called "工作" is found by "claude", and "Z.ai" finds z.ai. A group with nothing left is omitted. Nothing left shows the same "No matches" line (zh-Hans 没有匹配的项目). The typed text is held by the shell, so opening an account and coming back, or changing language, keeps it. It is a different field from the sidebar's.

**The menu beside that field is the order inside each group** (`AppSettings.providersListOrder`, key `settings.providersListOrder`). **Alphabetical** (zh-Hans 字母序, raw `name`) is the default: the name on the row, `localizedStandardCompare`, with the account id breaking a tie — the same comparison the rail uses before anyone arranges it. **Panel order** (zh-Hans 面板顺序, raw `panel`) is the rail's order, including an arrangement somebody made. The choice is stored and calls neither `onChange` nor `onLayoutChange`. An unknown stored value is alphabetical. There is no popularity order. Nothing in the app ranks providers by how often they are opened or enabled. Token spend is off until switched on and only covers agents that keep local transcripts, so it is not a ranking of this list.

**Accounts start in name order** (`AppSettings.orderedAccounts`), not declaration order, so a rail nobody has arranged can be looked up rather than scanned. An arrangement somebody made is kept, with unmentioned accounts after it by name; an added account sorts by its own label. The Providers page uses that order while its menu is on Panel order. Alphabetical does not rewrite the rail.

## Provider chooser

`ProviderSetupView` is shared by initial setup and upgrade suggestions. Each provider is a native checkbox with its name, a presence-only **Detected on this Mac** hint, and its access description (`Provider.monitoringAccessDescription`, in `ProviderAccess.swift`). Providers are listed in the sidebar's two groups, subscriptions first, each group detected-first then by name; every checkbox starts off, and **Select detected services** is an explicit action. The list scrolls while the explanation and buttons stay visible. Access descriptions may wrap: they must be readable before a service is selected.

On initial setup, **Done** is disabled until at least one is selected; closing the window leaves monitoring stopped. On an upgrade, the chooser lists only newly supported detected providers and may be completed with none selected; existing choices keep running. Restoration and dismissal: [../architecture.md](../architecture.md#provider-choice-before-monitoring).

Settings stays reachable after dismissing the initial chooser; Appearance points to the provider panes. A disabled primary provider's pane shows the same access description above **Show in panel**; enabling it starts monitoring. Its connection, sign-in, diagnostics and usage controls appear after the initial choice, but Current usage says **Not shown** and Retry is unavailable while it is off. Opening a disabled pane does not preload its saved key, read its history, or start any provider request or Codex's app server.

## Copy

**Subtitles are one line.** Say what the control does; reasoning belongs in docs. Exceptions: the money card's provenance and the estimate caption, which exist so an inferred figure is not read as reported.

**A joined sentence needs no extra space after a Chinese full stop (`。`).** `appearanceSubtitle` and `UsageAlerts.joined` insert a separator only when the first half does not end in one.

While the Appearance picker is on Glass, a **Transparency** slider appears under it (`glassTransparency`, 0–1, default 0.5): right is clearer, and past the default the text turns from white to black. It sets no `onChange` — that refetches every provider, and a slider fires continuously. The Glass segment is 液态玻璃 / 液態玻璃; it was 毛玻璃 while the panel rendered glass inactive and it really was frosted ([../decisions/liquid-glass.md](../decisions/liquid-glass.md)). Light, and Auto when the Mac is light, draws the light panel (#74): grey 0.97, the hairline inside the outline, deeper usage colours, and the same light surface at the notch. Glass stays dark until the slider passes three quarters. Appearance stays one control — dark, light, auto, glass — rather than a colour switch beside a glass switch. **Progress bars** (Continuous / Segmented) sit on this pane too; the menu's bars follow them, so the row stays available while the panel is hidden.

The window's title is **Blinky**. The first launch opens on **Appearance**. After that it opens on the pane last shown (`settings.lastPane`, `SettingsPaneBookmark`); a removed account opens Providers. `pulse://settings` still opens Appearance. ### Appearance

- **Round ends** (`AppSettings.usesRoundEnds`, **off** by default; off is the rail Pulse shipped with) sits with Size and Spacing because it changes what the rail measures. It is one switch over the rail's ends, the flare into the screen edge, the end padding and the card's tail: split, a round end could sit on the other style's padding, the first ring hard against the curve it should be centred in. [panel-geometry.md](panel-geometry.md)
- **Progress bars** (`AppSettings.usageBarStyle`, Continuous by default, or Segmented) draws the limit bars on the card and in the menu. The row stays available while the panel is hidden, because the menu's bars follow it.
- **Appearance** (`AppSettings.panelAppearance`: dark, light, auto, glass) is one control, not a colour switch beside a glass switch. Light, and Auto when the Mac is light, draws the light panel (#74): grey 0.97, the hairline inside the outline, deeper usage colours, and the same light surface at the notch. Glass is 液态玻璃 / 液態玻璃 in Chinese; it was briefly 毛玻璃 while the glass rendered inactive and really was frosted ([../decisions/liquid-glass.md](../decisions/liquid-glass.md)). Past three quarters the panel's scheme follows. The slider sets no `onChange`, which refetches every provider, because a slider fires continuously. The percent is that fraction shown as a whole number; it is not stored on its own.
- **Ring activity animation** (`AppSettings.animatesRingActivity`, on by default) closes Look. It gates the two turning marks — white for a working CLI, the usage colour for a fetch — not whether Pulse tracks either fact. [rings-and-surface.md](rings-and-surface.md#activity-mark)
- **Colour** is the last group. **Ring colour scheme** (`AppSettings.ringColourScheme`, Red alert / Gradient / Quiet, default Red alert) owns every usage colour on the panel. **Turn red at** is nested under Red alert and Quiet (`AppSettings.warningThreshold`, 60–90%): green to red under Red alert, green to muted grey under Quiet. Gradient never draws red, including when spent. Quiet keeps green below the threshold. **Alert colour when docked** (`AppSettings.dockShowsAlertColor`, on by default) closes the group. It gates only `FloatingUsagePanelContent.alertTint` — the collapsed sliver's colour, or at a physical notch the thin edge below the housing; the rings are unaffected. ### Usage

What the floating card shows, apart from its colours. The pane is **Usage** (用量). The case is still `.usageCard`, and the stored keys are unchanged. The old name Usage card remains a search term.

- **Figures** (zh-Hans 数字与内容) holds the percentages, where the figure sits, Show what's left, the second limit, and the reset clock. **Time ring direction** follows **Time until reset** and is hidden while the clock is off: a two-way menu, elapsed (the default, so existing installations do not reverse) or remaining (starts full, empties toward reset). It changes only the neutral outer arc, independently of **Show what's left**, which controls the coloured ring and its figure. [rings-and-surface.md](rings-and-surface.md#window-clock-arc)
- **Exhaustion estimate** (用尽预估) is the forecast line (`showsForecast`, on unless stored off; the row is **Show the estimate**) and, while it is on, Countdown up to, May run out before reset, and Say roughly when. Those three hide while the line is off; the hours and the two switches stay stored. The line is written under the weekly limit, or under the longest other stated limit when there is no weekly one. A five-hour limit is left out. With the row on, an unused or lightly used window still says it is expected to last, including when the service did not state that window's length. A window that has barely opened and is already well used still shows the estimate, with a dimmer line under it that the early pace is only a guide. Lasting is a restrained green; a pace that may not last is a restrained amber. That note uses the footnote size and the secondary colour. [../refresh-and-data.md](../refresh-and-data.md#forecast-burnrate)
- **Which accounts** is one list. Its subtitle says the estimate and the running-out notices both use it. Every account on the panel, or a list of switches that starts from whoever is shown. The control moved here from Notifications; it was not copied.

### Position and behavior: Order

- **The Order group lists only the accounts switched on** — listing every provider, the rest marked "Not shown", buried the few being arranged. Moves reorder the shown ones (`AppSettings.move`); switched-off accounts keep their order behind them, so one switched on later arrives at the end of the rail.
- **Reorder by dragging a row or with the arrows.** Dragging is needed at seventy-odd providers (bottom to top was already twenty-four clicks at twenty-five); the arrows stay as the precise one-place move, the only keyboard path, and the only one with accessibility labels.
- **`AppSettings.move(_:onto:)` is "take its place"**: the dragged row is removed first, so dropping downward lands after the target and upward before it. The payload is the account id as a plain `String`, so a text drag from another app can highlight a row, and the drop is then rejected (`AccountKey(id:)` fails, or the id names no account). A custom `UTType` would stop the highlight but must be declared in the bundle's `Info.plist`, making `swift run` differ from the shipped app for a cosmetic case.
- **Reset order** closes the group, disabled unless `hasCustomOrder` — which compares the accounts, not whether anything is stored, since dragging a row down and back up stores a list equal to the default. `resetOrder()` clears `providerOrder` rather than writing the default into it, so a provider added in a later version still arrives at the bottom of the rail.

### General

**Startup and windows**, then the Application group. The rows below are in that order:

- **Open at login** (zh-Hans 开机启动, zh-Hant 開機啟動). The first row under Startup and windows. It registers the bundle that is running (`SMAppService.mainApp`, or the launch agent when there is no bundle). After `InstalledAppName` renames `Pulse.app` to `Blinky.app`, the relaunched copy registers that bundle once when the switch was on (`LoginItem.refreshAfterBundleMoved`). [../architecture.md](../architecture.md#login-item), [../releasing.md](../releasing.md).
- **Show main window when opened at login** (`AppSettings.showMainWindowAtLogin`, key `settings.showMainWindowAtLogin`, **off by default**, zh-Hans 开机自启时显示主窗口). Nested under Open at login and hidden while that switch is off; the stored value is kept. A manual launch opens the main window either way. How a login launch is told apart: [../architecture.md](../architecture.md#login-item).
- **Always show Dock icon** (`AppSettings.alwaysShowsDockIcon`, key `settings.alwaysShowsDockIcon`, **off by default**): Blinky is a regular app from launch, Dock icon and ⌘-Tab included, with every window closed. `LSUIElement` stays true; the policy is set in `applicationWillFinishLaunching`.
- **Show Dock icon while a window is open** (`AppSettings.showsDockIconInSettings`, key `settings.showsDockIconInSettings`, **on by default**): Pulse is a regular app while the main window, a recap, or the service chooser is open, and a menu bar app again when the last closes, through `DockPresence`. Nested under Always show Dock icon and hidden while that switch is on. The label used to name Settings and a recap; the key and the default did not change.
- **Hide menu bar icon** (`AppSettings.hidesMenuBarIcon`, off by default) removes only the AppKit status item; the floating panel's secondary-click menu or a successfully registered global shortcut still opens Settings. If neither remains, hiding the icon shows the panel first; before the initial provider choice, where there is no panel, the request is refused. Hiding that panel later, clearing the last shortcut, a registration conflict, or restoring an unsafe saved combination brings the icon back, and the row's subtitle then says why (`AppSettings.menuBarIconRestoreNote`, key `settings.menuBarIconRestoreNote`). The note clears once a panel or a registered shortcut is a way back. Changing it does not refresh provider data.
- **Show floating panel** (`AppSettings.isPanelVisible`, key `settings.panelVisible`) is the same switch as Position and behavior. Both rows write that one value.
- **Show usage in the menu bar** (`AppSettings.showsUsageInMenuBar`, off by default; greyed out while the icon is hidden): the status item shows the fullest ring's mark and figure (following **used / left**), red past the warning line, with the account and limit in its tooltip. While on, two rows follow. **Menu bar shows**: the fullest ring, or one account on the rail (`menuBarAccount`; an account switched off or removed falls back to the fullest). **Menu bar style** (`menuBarStyle`): **Figure**; a small **Ring** beside the mark; or **Split** — the account-wide timed limits side by side with short names, shortest first, at most two (`5h/9%  周/15%`), each red on its own past the warning line. Scoped limits (one model's week) are not split; an account with fewer than two falls back to the figure, and the ring needs a limit, so money and "no reading" stay text.
- **Usage panel in the menu** (`AppSettings.showsMenuDashboard`, **off by default**, the group's last row, greyed out while the icon is hidden): the menu bar item opens on a **dashboard** (`MenuDashboard`, a SwiftUI view hosted in the menu's first item), independently of **Show usage in the menu bar**. Off, the menu opens on **Refresh** and the plain items. Always on in 1.6.0; a switch since, as the largest thing Pulse puts on screen unasked.

**The menu dashboard:**

- **Tabs**: **Overview** and one per account on the rail, labelled while there are five or fewer, marks only past that; the menu remembers the tab (`MenuDashboardModel`).
- **Overview** lists every account: mark, name and figure, and beneath them the limit and its reset, red past the warning line, "No reading" rather than a zero. A row opens that account's tab.
- **An account's tab** shows its plan and how long ago it was read; every limit with a bar, its reset and used/left figure; Codex's reset credits; and what is left of a balance or of Codex's credits where reported (a **Credits** or **Balance** heading over "2500 remaining", with no bar, because no provider states the total — CodexBar's bar divides by a figure OpenAI does not report). Only with **Token spend** on, for the primary account of a provider that keeps local transcripts, it adds the four figures of the account's usage history in Settings (today, the last 31 days, the busiest day, all time; each estimated cost over tokens) and a daily token chart, labelled as an estimate at API prices. That ledger is read incrementally when the tab opens, and again when it opens more than five minutes later so "Today" stays today's (`MenuDashboardModel.ledgerLifetime`).
- **Below the dashboard**: **Open <provider> usage page** while an account's tab is open and `Provider.usagePage` knows one (a table in `UsagePages.swift`, pages only, never an API or Referer address), then **Refresh** (⌘R, a full pass), which stays with the dashboard off. Figures end on the edge the key equivalents do (`MenuDashboard.trailing`). The rail's own right-click menu has none of this.
- **Both menus carry Show floating panel**, checked while the rail is on screen (the Settings → Position switch, and the same switch under General → Startup and windows). Hiding the panel when it and the icon were the last way back brings the icon back (`settingsChanged`) and General says so. Reopening Pulse while it runs (the Dock, Applications, Spotlight) opens the main window, and the chooser as well when a service is still unchosen or an upgrade suggestion is waiting (`applicationShouldHandleReopen`), so no combination is a dead end.

**Currency**, below Language (`CurrencySettingsGroup`): **Show estimates in** picks the currency of every estimate (`AppSettings.displayCurrency`, dollars by default); its subtitle says what is converted and that a service's own balances and charges are not. For any currency but the dollar, two more rows: **Exchange rate** ("1 USD = [field] CNY", the field's placeholder the day's rate; the subtitle says whose rate is used and when it was updated, or that estimates stay in dollars until there is one; a typed rate that is not a positive number is refused and the field goes back to the kept one) and **Rate source**, the "Rates By Exchange Rate API" link the source's terms ask for — a credit, written the same in every language. Rules: [../refresh-and-data.md](../refresh-and-data.md#currency).

**Shortcuts**, above Language: two rows, empty until set, each a `ShortcutField` — click, press the combination; ⎋ leaves it alone, ⌫ clears it. The subtitle is the row's own line **unless** the window server refused the combination, which then replaces it. Setting one writes the setting and calls `GlobalShortcutMonitor.apply` at once; after both actions are applied, its registration callback rechecks the app-entry rule above. Shortcuts deliberately do **not** go through `AppSettings.onChange`, which refetches every provider. Rules, and why hot keys rather than an event tap: [input.md](input.md).

### Notifications

Every notice control is greyed out in an unbundled build. **When a limit comes back** is hidden while Warn at is Off (a reset is announced only for a window that was warned about); the stored switch is kept. The card rows in **Exhaustion forecast** stay usable there: they only change a line. **When a service is down** reads the providers' own status pages; its subtitle names no provider — any of the 44 with a page, switched-on ones only, and only what their accounts run on. **When a recap is ready** (`AppSettings.alertsOnRecap`, off by default) cannot be turned on while Token spend reading is off, since the month is known only from records Pulse has read (its subtitle says so); once on, it stays operable so it can be turned off. Switching it on does not call `reconsiderAlerts`: `AppSettings.onRecapAlertChange` asks for permission and checks the month. The first subtitle reports `UNAuthorizationStatus`, not the switches.

The pane is titled **Notifications** (通知). The estimate and **Which accounts** live on Usage. Four groups hold the notices, and a row's title does not repeat 通知: **Limit reminders** (Warn at, When a limit comes back), **Running out** (When it is running out — the switch that was “Notify when a limit is running out”, on, with one stage at 24 hours; Remaining hours; Will not last until the reset, off, `exhaustionNotifyBeforeReset`), **Service status** (When a reading stops arriving, When it is down), **Monthly recap** (When it is ready). The stages hide while When it is running out is off. **Add a stage** appends another, each row a stepper that shows its hours and Remove, and two stages cannot share an hour. Opening the pane asks for notification permission when a time-to-empty notice is on and macOS has not been asked yet. Changing a stage or either notice switch reconsiders the readings already held. The estimate itself is a layout setting, so it re-places the panel and fetches nothing. The running-out notices use the same limit as the estimate: the weekly one, or the longest other stated limit, never a five-hour window. Rules: [../notifications.md](../notifications.md#time-to-empty).

**Reset reminders** fire before a time (predicted Codex Resets `scheduled_for`, and each window's own `resetsAt`). Each **How early** menu is nested under its switch and hidden while that switch is off; the lead stays stored. **Celebrations** plays ribbons after a week or month turns over. The five-hour ribbon is nested under that switch and hidden while it is off; it is not a notification. **Test notification** sits at the foot of the pane. **Send** posts one notification now, asks for permission whatever else is switched on, and the row then says what came of it. Rules: [../notifications.md](../notifications.md), [../notifications.md](../notifications.md#test-notification).

An account pane gets a **Low balance** group where `Provider.reportsSpendableBalance` is true: a "warn below" figure in money. It is per account, not in the Notifications pane, because providers that report a balance do not share a currency; and not under Connection, which is about credentials and routes. The group used to be titled Notifications, which repeated the pane. [../notifications.md](../notifications.md)

### Network and refresh

The usage-interval group is named **Refresh**, not Updates. The manual proxy host and port are view-local text while edited. Return or leaving either field tries the pair; only a non-empty host and a whole port from 1 through 65535 replace the saved endpoint. Invalid text stays visible with the explanation on its own row, and nothing refetches on each keystroke.

### Experimental

### Token spend

The pane starts with **Read local usage records**, off by default on fresh installs and upgrades. While off it shows only that control and its explanation. Enabling it shows scan progress while a read is in flight, and the **Usage recaps** row. One button rather than one per period: the window switches between day, week, month and year itself, and a button for each repeated that control. The window's own controls (period, monthly price, hide project names, export) are in [../recap.md](../recap.md#the-window), next to the card they change.

## Controls

**Card borders are decorative and ignore hit testing**, so they cannot cover the controls or the charts' full-height hover targets. Chart readouts: [../token-spend.md](../token-spend.md), [../refresh-and-data.md](../refresh-and-data.md).

**SwiftUI `Picker` / `Menu` on macOS cannot be given a width.** `.frame`, min/max, `fixedSize` and a fixed-width custom label were measured (historical) and none moved the control. Right-align at `SettingsLayout.controlWidth` (180) as a *ceiling*; long labels truncate. An `NSPopUpButton` wrapper gave a true 180pt box and was removed because short labels floated in empty chrome; do not rebuild it without checking that first.

**The sidebar cannot be hidden** (`NavigationSplitView(columnVisibility: .constant(.all))`, `.toolbar(removing: .sidebarToggle)`). With SwiftUI's toggle, collapsing it and drawing it back at a width that could not hold sidebar and pane side by side overflowed both ways — the list past the left edge, the pane past the right — and the title bar showed an overflow "»". The sidebar is how the window is navigated, as in System Settings.

**Sidebar column: min 220, ideal 240, max 320**, sized to "Alibaba Coding Plan", the longest (brand) name (121.4pt of text at 13pt; "Xiaomi Coding Plan" 117.3), with the scroller always showing; at 200 it read "Alibaba Coding Pl…". `ideal` was scaled from a fourteen-character name that fit, not measured, so check a longer name in the running app. `min` matters most: AppKit saves the divider position, so `ideal` is read once per install while `min` clamps everyone.

**Sidebar icons are the text's colour** (`SidebarRowLabelStyle` in `SettingsSidebar.swift`): black, white in dark mode. A source list tints its icons with the accent colour, and two dozen blue marks down the list read as links rather than as places. The row lays out its own icon and title rather than recolouring the sidebar's: a `.foregroundStyle` on the icon did not override the tint, and `.listItemTint(.fixed(.primary))` held only for the rows on screen when the window opened — rows scrolled into view later were blue again (both checked in the running app).

**Default window: 920 × 660**, set on the `NSWindow`'s `contentRect`; the view's `minWidth` / `minHeight` (720 × 460) are the drag-down limit. The former 760 × 500 scrolled in both columns on opening. The size is not remembered: the window is rebuilt and `center()`ed on each launch.

**`ImageRenderer` cannot draw this window** (split view + AppKit controls). Check by running the app.

## About

Two groups. The first is the app: version and update state, where the usage figures come from, and the **source address**, with the URL itself as the subtitle so it can be typed.

**Opening the pane checks for an update** (`AppUpdate.probe`, Sparkle's `checkForUpdateInformation`), unless a check or update is already running: no Sparkle window, only the Version subtitle changes ("Checking…", then the answer), so "up to date" is current. It runs **even with Check automatically off** — that switch covers Pulse's own schedule; opening About is the reader asking. With **Notify first** left on, opening the pane also asks for notification permission if nobody has been asked yet. **Check now** and the Blinky menu's **Check for Updates…** (under About; zh-Hans 检查更新) call `AppUpdate.check` and open Sparkle's window. **Check for updates every** (检查更新间隔), the row under Check automatically, is a number and a unit — minutes, hours, days, or weeks — and the default is twelve hours. Through 1.5.24 the check was fixed at two hours. Changing it reschedules the next check without a restart. Sparkle will not arm a timer under an hour, so a shorter interval is Blinky's own timer calling `checkForUpdatesInBackground`, the same scheduled check the discovery choice already uses; an hour or longer is Sparkle's `updateCheckInterval`. Check now is not that timer. A scheduled check follows **When an update is found** (发现更新时), the row under that interval. **Notify first** (先通知, the default) posts a notification and opens that window when the notification is clicked. **Show the window** (直接打开窗口) opens it immediately. **Install silently** (自动安装) downloads on the scheduled check, then installs and relaunches Blinky without waiting for it to quit, with no notification and no update window before that install. After Blinky opens on the installed version, a notification names that version and what changed in this release; clicking it opens those notes, and when a notification cannot be posted the notes window opens instead. Check now still opens the window. A refused notification permission opens the window on a scheduled find under Notify first, so the update is not missed. Any path that shows the window brings it to the front ([../releasing.md](../releasing.md#sparkle)). Sparkle's own automatic-install checkbox is hidden; this picker is the control.

The second group is **Credits**: anything shipped here that somebody else made — the design it was built from, the provider marks, and the animated marks' geometry ([../decisions/bot-mark-geometry.md](../decisions/bot-mark-geometry.md)).

## Provider panes

**A provider with more than one route offers the choice, automatic by default; one with one route has that route named**, and the name belongs to the provider (`Provider.soleRoute`, an exhaustive `Provider` switch; omit the row when nil). A ternary (Cursor vs else Antigravity) once made the next single-route provider inherit Antigravity's sentence. Grok's row is Automatic, CLI login, or Blinky login. Automatic uses the CLI's saved login while it is still good, then the login from the Grok account row in Accounts.

**Each pane has its own refresh**, with the last reading's time; a rail click is not the only way.

**The credential field** (API key, session cookie, access keys) is masked, with an eye button between it and **Save** that shows what is typed. It hides again whenever the pane changes account. A first account that needs a credential Pulse has not got is seeded with the reason, not `.loading`; `loadAPIKeys` rewrites that only over a placeholder.

**Connection diagnostics** follows Connection on every account: latest check, check time, last successful reading, actual source of the displayed figures, explicit cache use, expandable route checks (the whole row toggles them: on macOS a disclosure group's title alone does nothing), and, when the check made web requests, expandable **Server replies**: each request's status, method and address, time, type and size, and the redacted body in a selectable monospaced box, with **Copy replies** ([../refresh-and-data.md](../refresh-and-data.md#connection-diagnostics)). A failed check stays visible even when the card shows cached figures. Retry asks only that account; diagnostic copy contains allowlisted metadata ([../refresh-and-data.md](../refresh-and-data.md)). The contextual next step focuses the credential field, reconnects the status line, starts the existing sign-in, reads the chosen browser, opens the relevant app, copies a login command, or opens setup help. Provider-specific mappings: [../providers/README.md](../providers/README.md).

**Added accounts** exist only for `supportsMultipleAccounts` (Claude Code, Codex, Grok, Grok Bot) and have **Sign in again**: successful reauthentication replaces the credentials in that slot, keeping its name and display preferences. They do not show ambient CLI source controls their fetch ignores. A cancelled sign-in, or an account removed while sign-in is pending, is not written back. One extra-account sign-in runs at a time; its **Cancel**, device code and error rows appear only on the panes of the provider it was started for, and other multi-account panes show a disabled **Sign in…** until it finishes. Flows: [../providers/authentication.md](../providers/authentication.md), [../providers/README.md](../providers/README.md).
